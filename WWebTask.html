WWebTask

new WWebTask(WOrm, url, db, getUserByToken, verifyClientUser, verifyAppUser, optopt) → {Object}

Description:

  • 任務調度伺服器

    身分驗證責任：框架（w-converhp、w-serv-hapi、w-serv-webdata、w-serv-orm）不驗證token，一律由本套件負責。連線閘（verifyConn）與執行身分（getUserIdByToken）皆須完整驗證（token有效、本系統使用者存在且啟用、部署方授權）；hapi apis路由各自驗證；函數層級另檢查角色或成員；公開入口只限列名者。 本套件之落實：連線閘、執行身分（資料通道本體__sysToken__，from固定為'main'）、登入檢查共用同一個完整驗證（token認證＋verifyClientUser）；本套件無自有使用者表，「使用者存在且啟用」由getUserByToken查無即回null保證。 函數層級（資料通道與HTTP REST共用同一張入口函數表，server/access.mjs）：管理類（頻道與成員之建立、修改、刪除）限系統管理者；訊息、任務、已讀游標、成員名冊限系統管理者或該頻道成員；檔案限系統管理者或任一頻道成員；頻道清單、統計、資料通道之channels／channelMembers的select只回呼叫者有權看之頻道之資料。 系統管理者＝getUserByToken所回使用者之isAdmin嚴格等於'y'；應用系統token之使用者用途反查回所綁使用者（等級同其使用者），系統服務用途反查回id以'app:'開頭且isAdmin為'y'（等級為系統管理者）；本套件不分辨用途，不讀isApp。頻道成員＝channelMembers中(channelId, memberId為呼叫者id, isActive為'y')之列（agent若以一般使用者認證，其user.id須為成員）。 公開入口（無須token）只有前端靜態檔；/api/*與資料通道一律須token，系統函數只公開'[sys:getFuncList]'（且本套件之getUserIdByToken對空token fail-closed）。

getUserByToken function

輸入處理函數，函數會傳入使用者token，通過此函數處理後並回傳使用者資訊物件，並至少須提供'id'、'email'、'name'、'isAdmin'欄位，且'isAdmin'限輸入'y'或'n'；本套件以'isAdmin'為'y'者為系統管理者（角色之唯一來源，函數層級之管理類限此類使用者），其餘為一般使用者（只能存取自己為成員之頻道）
verifyClientUser function

輸入驗證瀏覽使用者身份之處理函數，函數會傳入使用者資訊物件之淺拷貝與來源字串(from)，通過此函數識別後回傳布林值，允許使用者回傳true，反之回傳false。作用於登入檢查(/api/getUserByToken，from為'getUserByToken')與前端資料通道之每次請求(連線閘，from為w-converhp之apiType如'main'；執行身分每個函數呼叫前再驗一次，from為'main')，三者同一判定；拋錯或reject視同不允許。本套件於此函數通過後另自行要求角色與成員（見上），部署方只能在其上再收緊
verifyAppUser function

輸入驗證應用程序使用者身份之處理函數，函數會傳入使用者資訊物件與來源字串(from，為API名稱)，通過此函數識別後回傳布林值，允許使用者回傳true，反之回傳false。作用於對外HTTP REST API(agent面)；拋錯或reject視同不允許。本套件於此函數通過後另自行要求角色與成員（管理類不在HTTP REST；頻道內容限系統管理者或頻道成員），部署方只能在其上再收緊
