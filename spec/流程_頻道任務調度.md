# 流程_頻道任務調度

> 本文件描述人類使用者於 Web UI（聊天式工作區）內「檢視頻道階層樹 → 檢視頻道聊天時間軸 → 於頻道發訊（含上傳圖片之純圖訊息）→ 檢視統計儀表板 → 於後台檢視頻道資料」之操作流程, 供 e2e 嚴謹測試與後續報告產製之用. 登入採開發捷徑 token=sys (admin), 進站後預設停在頻道區.

## 觸發

使用者以系統管理者身分登入後進入主畫面. 左1 為近黑導覽 rail, 提供「統計 / 頻道 / 後台」三個區段. 預設停在頻道區: 左2 為階層頻道樹（專案 > 群組 > #頻道）與搜尋框, 點頻道後右側展開聊天工作區（標題列含頻道名 / 麵包屑 / 任務 pills / agent chip, 中央為訊息時間軸, 底部為發訊區）. 使用者點 rail 切換區段; 於頻道區選頻道、檢視時間軸訊息、於發訊區輸入並送出訊息; 於統計區檢視儀表板計數; 於後台區之頻道子頁檢視頻道資料表.

## 重要流程

- **E2E-001**: 登入後預設停在頻道區, 階層頻道樹顯示專案與頻道
  - description: 使用者以 admin (token=sys) 登入後, 主畫面預設停在頻道區, rail 之「頻道」項為選取態. 左2 頻道樹依各頻道之 levels 欄建巢狀階層（專案 > 群組 > #頻道）. 種子含四個頻道, 分屬「數據平台」(ETL 管線 / 報表產製) 與「電商平台改版 > 後端組」(訂單服務 / 金流串接) 兩專案群組. 預期使用者在頻道樹看到此群組階層與其下頻道. 本案例為頻道區初始檢視, 不做任何輸入.
  - flow:
    - 測試資料: 四個頻道種子——`訂單服務`(levels=`電商平台改版.後端組`)、`金流串接`(levels=`電商平台改版.後端組`)、`ETL 管線`(levels=`數據平台`)、`報表產製`(levels=`數據平台`); 由頻道種子提供, 各 case 共用同一 base seed.
    - 操作: 自登入後之主畫面起 (預設頻道區), 不另操作.
    - 驗證: 語意——頁面文字含頻道名 `訂單服務`、`ETL 管線` 與群組名 `數據平台`、`電商平台改版`; 視覺——框頻道階層樹之各列（專案、群組與頻道列之聯集, 不含樹下方空白）, baseline `test/pics/channeltask/channeltask-{eng,cht}-E2E-001-channels-tree.png`（2026-09-28 原載「框左2 頻道階層樹」→ 改為本句: 原框整個左2 面板, 七列之下約 600px 空白一併框入）.
    - 雙語: eng / cht 各一輪 (頻道名 / 群組名為資料恆中文, 雙語差異僅在 rail 標籤與樹標題等 i18n chrome).
    - 清理: base seed 為唯讀檢視, 不產生副作用; 由 setup 每 case 重置 DB, 本段不另清理.

- **E2E-002**: 點頻道, 聊天時間軸顯示種子訊息與任務徽章
  - description: 使用者於頻道樹點「訂單服務」頻道, 右側展開該頻道聊天工作區. 種子於該頻道含四則訊息: 人類歡迎語 (text)、agent 上線語 (text)、人類開任務訊息 (task)、agent 任務回應 (taskReply). 預期時間軸由上而下依時序顯示此四則訊息（本人類訊息靠右、agent 訊息靠左）, task 與 taskReply 訊息另以類型徽章標示; 標題列另顯示任務狀態 pills（待處理 / 處理中 / 已完成計數）. 訊息時間戳為固定值以確保畫面穩定.
  - flow:
    - 測試資料: 頻道 `訂單服務` 下四則固定時間戳之種子訊息 (text / text / task / taskReply); 與 base seed 共用.
    - 操作: 自頻道區起 → 點頻道樹中之「訂單服務」頻道列.
    - 驗證: 語意——時間軸文字含 `Welcome to the demo channel.`、`Agent online and ready to take tasks.`、`Please summarize the quarterly report.`、`Summary completed: revenue grew 12% QoQ.`, 並含任務徽章文字（eng: `Task` / `Task reply`; cht: `任務` / `任務回應`）與標題列任務 pills（eng: `Pending` / `Done`; cht: `待處理` / `已完成`）; 視覺（點頻道列一個操作兩張）——①點擊前, 框住頻道樹「訂單服務」列整列 `test/pics/channeltask/channeltask-{eng,cht}-E2E-002-1-click-channel.png`; ②點擊後, 框時間軸內之訊息（日期分隔與四則訊息之聯集）`...-E2E-002-2-chat-view.png`（2026-09-28 原載「框聊天時間軸區」→ 改為本句: 原框整個時間軸區, 四則訊息下方約 350px 空白一併框入; 同日依「一個使用者操作＝點擊前、點擊後各一張」補①, 原單張圖鍵 `E2E-002-chat-view` 改為 `E2E-002-2-chat-view`）. 本案之①②兼作 E2E-003/006/007/008/011/012 首步「點頻道列」之共用圖.
    - 雙語: eng / cht 各一輪.
    - 清理: 唯讀檢視無副作用; 由 setup 每 case 重置 DB, 本段不另清理.

- **E2E-003**: 於發訊區輸入訊息並送出, 新訊息出現於時間軸
  - description: 使用者於頻道「訂單服務」之底部發訊區輸入一則文字訊息並以 Enter 送出. 預期送出成功後輸入內容出現於時間軸（本人類訊息靠右）, 且發訊區輸入框清空. 本案例為真實輸入與送出之操作鏈, 重點驗證「輸入 → 送出 → 出現 + 清空」之語意鏈. 因新訊息帶即時時間戳, 視覺 baseline 改對「發訊區（輸入框 + 工具列 + 送出鈕）」於送出前（內容填妥）框紅框截圖, 避開動態時間戳區.
  - flow:
    - 測試資料: 頻道 `訂單服務`; 與 base seed 共用. 本案例會於該頻道新增一則人類文字訊息 (副作用).
    - 操作: 自頻道區起 → 點頻道樹中之「訂單服務」頻道列 → 於底部發訊區輸入框輸入一段文字 → 按 Enter 送出.
    - 驗證: 語意——送出後時間軸文字含剛輸入之訊息內容, 且發訊區輸入框值為空; 視覺——框底部發訊區（輸入框 + 工具列 + 送出鈕, 內容填妥送出前, 避開含即時時間戳之時間軸）, baseline `test/pics/channeltask/channeltask-{eng,cht}-E2E-003-chat-send.png`（首步「點頻道列」共用 `...-E2E-002-1-click-channel.png`、`...-E2E-002-2-chat-view.png`, 不另設標準圖）.
    - 雙語: eng / cht 各一輪 (輸入內容含語系後綴, 兩語系 baseline 之發訊區內容與按鈕文字各異).
    - 清理: 移除本案例新增之訊息, 保留 base seed; 由 setup 每 case 重置 DB 達成 (刪 db 重建種子).

- **E2E-004**: 切統計區, 儀表板顯示概況計數
  - description: 使用者點 rail 之「統計」項切到統計區. 統計儀表板上半 OVERVIEW 區顯示三張卡——頻道數 / 訊息數 / 任務總數; 下半 TASK BREAKDOWN 區顯示任務各狀態計數（待處理 / 處理中 / 已完成 / 失敗）. 計數來源為後端統計, 對 pristine 種子為固定值（頻道 4、訊息 4、任務 3）. 預期 OVERVIEW 區呈現三卡標題與其計數值.
  - flow:
    - 測試資料: base seed（四頻道 / 四訊息 / 三任務）; 與 base seed 共用.
    - 操作: 自頻道區起 → 點 rail 之「Stats」/「統計」項切到統計區.
    - 驗證: 語意——OVERVIEW 區文字含三卡標題（eng: `Channels` / `Messages` / `Tasks`; cht: `頻道數` / `訊息數` / `任務總數`）及計數值（頻道 4、任務 3）; 視覺（點 rail 一個操作兩張）——①點擊前, 框住左側 rail 之「Stats」/「統計」項整顆（圖示與文字）`test/pics/channeltask/channeltask-{eng,cht}-E2E-004-1-click-stats.png`; ②點擊後, 框 OVERVIEW 卡片區 `...-E2E-004-2-stats.png`（2026-09-28 補①; 原單張圖鍵 `E2E-004-stats` 改為 `E2E-004-2-stats`）.
    - 雙語: eng / cht 各一輪.
    - 清理: 唯讀檢視無副作用; 由 setup 每 case 重置 DB, 本段不另清理.

- **E2E-005**: 切後台區, 頻道子頁資料表顯示階層欄與頻道列
  - description: 使用者點 rail 之「後台」項切到後台區, 後台左2 子選單預設選取「頻道」子頁, 右側以資料表（ag-grid）列出全部頻道. 資料表含「頻道名 / 階層 / 頻道描述 / agent / 擁有者」等欄. 預期資料表顯示階層 (Levels) 欄表頭與四個頻道列, 各頻道之階層欄呈現其 levels 值. 本案例為後台資料檢視.
  - flow:
    - 測試資料: 四個頻道種子（含 levels 欄值）; 與 base seed 共用.
    - 操作: 自頻道區起 → 點 rail 之「Admin」/「後台」項 → 後台預設停在「頻道」子頁.
    - 驗證: 語意——資料表文字含階層欄表頭（eng: `Levels`; cht: `階層`）、頻道名 `訂單服務` 與其階層值 `電商平台改版.後端組`; 視覺（點 rail 一個操作兩張）——①點擊前, 框住左側 rail 之「Admin」/「後台」項整顆 `test/pics/channeltask/channeltask-{eng,cht}-E2E-005-1-click-admin.png`; ②點擊後, 框後台頻道資料表之標頭與四個頻道列 `...-E2E-005-2-admin-channels.png`（2026-09-28 原載「框後台頻道資料表」→ 改為本句: 原框表格外框, 列下方約 590px 空白一併框入; 本檔其餘資料表同此改法; 同日補①, 原單張圖鍵 `E2E-005-admin-channels` 改為 `E2E-005-2-admin-channels`）. 本案之①兼作 E2E-009/010/013 首步「點後台」之共用圖.
    - 雙語: eng / cht 各一輪.
    - 清理: 唯讀檢視無副作用; 由 setup 每 case 重置 DB, 本段不另清理.

- **E2E-006**: 於發訊區上傳圖片並送出純圖訊息, 圖片出現於時間軸
  - description: 使用者於頻道「訂單服務」之發訊區點附圖鈕, 選取一張本地圖片, 發訊區出現該圖之預覽縮圖. 使用者不輸入任何文字, 直接點送出, 送出一則「純圖訊息」(內容空、僅帶附件). 預期送出成功後時間軸出現一則新訊息且含該圖片附件, 發訊區輸入框維持為空. 本案例驗證「貼多圖」之圖台互動鏈與「純圖訊息」(內容空時仍可憑附件送出) 之行為. 因新訊息之附件帶即時產生之檔案識別與時間戳, 視覺 baseline 改對「發訊區預覽縮圖區」於送出前框紅框截圖, 避開動態值區.
  - flow:
    - 測試資料: 頻道 `訂單服務`; 與 base seed 共用. 本案例會於該頻道新增一則含圖片附件之人類訊息 (副作用), 並於圖台新增一筆檔案.
    - 操作: 自頻道區起 → 點頻道樹中之「訂單服務」頻道列 → 於發訊區點附圖鈕並選取一張本地圖片 → 等預覽縮圖出現 → 不輸入文字 → 點「Send」/「送出」按鈕.
    - 驗證: 語意——送出後時間軸含一則帶圖片附件之訊息（附件圖以頻道檔案串流呈現）, 且發訊區輸入框值為空; 視覺——框發訊區預覽縮圖區（內容備妥送出前, 避開含即時檔案識別 / 時間戳之時間軸）, baseline `test/pics/channeltask/channeltask-{eng,cht}-E2E-006-chat-upload-image.png`（首步「點頻道列」共用 `...-E2E-002-1-click-channel.png`、`...-E2E-002-2-chat-view.png`, 不另設標準圖）.
    - 雙語: eng / cht 各一輪.
    - 清理: 移除本案例新增之訊息與圖台檔案, 保留 base seed; 由 setup 每 case 重置 DB（刪 db 重建種子、清圖台檔案表與實體目錄）達成.

- **E2E-007**: 送出挾帶 HTML 之訊息, 內容經消毒後安全渲染不執行 JS
  - description: 使用者從頻道樹點選「訂單服務」後, 於聊天頁底部發訊區輸入一段含 HTML 標籤之文字, 例如夾帶程式之圖片標籤後接一段說明文字, 再按「Enter 鍵」送出. 訊息立即寫入頻道並出現在時間軸最下方, 自己發出之訊息顯示於右側, 並標示發送者與送出時間; 內容中之文字照常顯示, 圖片標籤只呈現為無法載入之圖片圖示, 其中夾帶之程式不會執行. 送出後發訊區輸入框隨即清空; 訊息送出後無法於畫面上撤回或刪除. 系統於顯示每則訊息前都會先過濾危險內容, 不需任何設定, 便於在頻道中貼上含標籤之片段, 而不必擔心他人夾帶之程式在自己的瀏覽器執行. 若送出失敗, 畫面會以對話框顯示「訊息傳送失敗」接失敗原因, 輸入內容會保留, 可修正後再送一次.
  - flow:
    - 測試資料: 頻道「訂單服務」; 與 base seed 共用. 本案例會於該頻道新增一則含 HTML 之人類訊息（副作用）. 送出前開啟測試實例之固定時鐘, 新訊息之送出時間寫入為 `2026-01-02T09:00:00.000+08:00`（晚於種子之次日）, 送出後即關閉.
    - 操作: 自頻道區起 → 點頻道樹中之「訂單服務」頻道列 → 於發訊區輸入框輸入挾帶惡意 HTML 之訊息 → 按 Enter 送出.
    - 驗證: 語意——(1) 惡意 handler 未執行（無 JS 副作用）; (2) 時間軸渲染後之 HTML 不含 `onerror` 屬性; (3) 訊息之純文字內容仍保留; 視覺（輸入一個欄位、按 Enter 送出兩個操作, 輸入後之圖兼作送出前之圖）——①輸入前, 框住發訊區輸入框整顆 `test/pics/channeltask/channeltask-{eng,cht}-E2E-007-1-type-payload.png`; ②輸入後、送出前, 框住發訊區（輸入框 + 工具列 + 送出鈕）`...-E2E-007-2-payload-typed.png`; ③送出後, 框住時間軸最下方新出現之該則訊息（含發送者頭像）`...-E2E-007-3-sanitized.png`（首步「點頻道列」共用 `...-E2E-002-1-click-channel.png`、`...-E2E-002-2-chat-view.png`, 不另設標準圖）. 修改留痕（2026-09-29）: 原載「語意-only, 不另存 baseline（因渲染後訊息帶即時時間戳, 且已消毒與未消毒之純文字視覺無從以像素區辨）」→ 改為本句: 業主裁示補圖; 時間戳改以測試實例之固定時鐘取得確定性; 消毒與否仍由語意 (1)(2) 判定, 三張圖為操作手冊之用.
    - 雙語: eng / cht 各一輪（消毒與語系無關, 兩語系下皆須成立）.
    - 清理: 移除本案例新增之訊息, 保留 base seed; 由 setup 每 case 重置 DB 達成; 固定時鐘於送出後關閉, 下一案重建種子時亦再關閉一次.
    - 備註: 固定時鐘之作法——測試實例後端以 `node --import test/tools/fakeNow/register.mjs` 啟動, 本專案寫入時間欄之 `wsemi` `nowms2str` 由替身 `test/tools/fakeNow/nowms2str.mjs` 取代, 僅於標記檔存在時回傳錨點（`test/tools/e2e-setup.mjs` 之 `setFakeNow` / `clearFakeNow`）; 其餘案例與 api 測試仍為真時鐘. ①之框內右側為輸入框本身之空白打字區（操作目標整顆）.

- **E2E-008**: 於頻道聊天頁開啟本頻道成員管理, 完成成員新增 / 更新 / 刪除
  - description: 使用者於頻道「訂單服務」之聊天頁標題列點「成員」入口, 開啟本頻道成員管理視窗. 因視窗綁定當前頻道, 不再顯示頻道選擇器（免再選頻道即可管理該頻道成員）. 視窗載入該頻道成員 agent-demo, 成員類型欄以在地化文字顯示（agent → `Agent`; human → `Human` / `人類`）. 使用者切換編輯模式, 完成一輪完整成員 CRUD: 新增一列（預設類型 human）並儲存（Create）; 於資料表就地編輯該成員之角色欄並儲存（Update）; 勾選該成員、按刪除並確認（Delete）. 本案例為承接式 journey（開啟 → 新增 → 更新 → 刪除之狀態逐步推進, 後段承接前段真實副作用, 屬單一 case 多階段）. 每階段以「頻道成員實際內容」觀察後端副作用（成員增 / 改 / 刪）. 視覺 baseline 對檢視模式之成員視窗（僅 agent-demo 一列, 種子時間戳固定 → 穩定）截圖; CRUD 各階段帶動態成員識別碼不另存視覺.

## 規則摘要

- **送出入口與連按**（D16, 2026-09-29）: 有副作用之送出入口——發訊（發送鈕、輸入框 Enter; `Composer.vue`）、頻道與成員之儲存與刪除（`LayoutContentChannels.vue` / `LayoutContentMembers.vue`; 後台與聊天頁成員視窗共用）、任務重試與送出回應（`LayoutContentTasks.vue`）、登出（`Rail.vue`）——一律經 `$ui.runSubmit(key, …)`（核心 `src/plugins/submitGuard.mjs`）: 同一操作之流程（自觸發起至結果訊息框關閉; 有確認框者自開確認框起）進行中再觸發即略過, 發送鈕之滑鼠 / 鍵盤 Enter 與輸入框 Enter 共用同一狀態（key `postMessage`）. 全頁 loading、確認框與結果訊息框（WDialog）只擋滑鼠、不搶焦點, 故焦點留在按鈕或輸入框時之鍵盤連按須由流程狀態擋下. 按鈕之 promiseUnlock 鎖交給 runSubmit, 於請求結束（`updateLoading(false)`）釋放; 有確認框者開框前即釋放. 登出確認後轉址時保持占位至頁面離開.
- **後端占位**（D16）: 同一操作者對同一頻道之發訊處理中再送出回 `sendInProgress`; 對同一頻道 / 成員列之儲存回 `saveInProgress`、刪除回 `deleteInProgress`; 皆不寫入、不排隊（依序呼叫、不同操作者不受影響）. 重試與送出回應沿用既有「同任務序列化 + 狀態守衛」（第 2 次必被拒: `errTaskNotResettable` / `errTaskNotRunning`）. 上述 key 於 UI 不可達（前端流程狀態先擋）, 僅 API 直打之並行會收到.
